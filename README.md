# أرشفة Discord إلى Google Sheets

سكربت Python يعمل على GitHub Actions دون جهاز دائم أو سيرفر. يقرأ REST API فقط، ويؤرشف رسائل المستخدمين في جدول خاص بك. يبدأ من أقدم الرسائل المتاحة، ثم يستكمل من حيث توقف. لا يحتاج البوت إلى الظهور Online.

## 1. إنشاء بوت Discord

1. افتح [Discord Developer Portal](https://discord.com/developers/applications)، ثم **New Application**، واختر اسمًا.
2. افتح **Bot**، وأنشئ البوت إذا لزم. فعّل **Message Content Intent** ضمن Privileged Gateway Intents. هذه الصلاحية لازمة لمحتوى الرسائل حتى مع REST. التطبيقات الكبيرة قد تحتاج موافقة Discord.
3. من **Reset Token** انسخ رمز البوت واحفظه مباشرة في GitHub Secret أدناه. لا تضعه في الكود أو ترسله في المحادثات.
4. من **OAuth2 → URL Generator** اختر scope باسم `bot` وصلاحيتي **View Channels** و**Read Message History**. افتح رابط الدعوة وأضف البوت إلى سيرفرك. لا يحتاج Administrator أو Send Messages.
5. تأكد أن إعدادات القناة نفسها تسمح للبوت بالصلاحيتين. للقنوات الخاصة أضف البوت إلى قائمة المسموح لهم.
6. في تطبيق Discord افتح **User Settings → Advanced → Developer Mode**. اضغط بزر الفأرة الأيمن على قناة تجريبية ثم **Copy Channel ID**.

القنوات النصية والخيوط قابلة للقراءة إذا كان البوت يستطيع الوصول إليها. ضع ID كل خيط مطلوب صراحة؛ لا يبحث السكربت عن خيوط المنتدى تلقائيًا. لا تستخدم ID تصنيف أو منتدى بدل قناة رسائل.

## 2. Google Sheets وService Account بالتفصيل

1. أنشئ [جدول Google](https://sheets.google.com) جديدًا وفارغًا.
2. افتح [Google Cloud Console](https://console.cloud.google.com/)، واضغط قائمة المشاريع أعلى الصفحة، ثم **New Project**. أنشئ المشروع وحدده.
3. افتح **APIs & Services → Library** وابحث عن **Google Sheets API**، ثم اضغط **Enable**. لا تحتاج إلى تفعيل Drive API لهذا المشروع.
4. افتح **IAM & Admin → Service Accounts → Create service account**. أدخل اسمًا مثل `discord-archiver`، واضغط **Create and continue**. اترك صلاحيات المشروع فارغة ثم أكمل؛ الوصول إلى الجدول يأتي من مشاركته.
5. افتح حساب الخدمة الجديد، ثم **Keys → Add key → Create new key → JSON**. سيُنزل ملف مفتاح خاص. إذا كانت مؤسستك تمنع إنشاء المفاتيح، يلزم التواصل مع مسؤولها.
6. انسخ عنوان **Email** لحساب الخدمة، وهو ينتهي بـ `iam.gserviceaccount.com`.
7. ارجع إلى الجدول واضغط **Share**، وأضف هذا البريد بصلاحية **Editor**. أبقِ الوصول العام Restricted.
8. انسخ معرّف الجدول فقط من الرابط: الجزء بين `/d/` و`/edit`. هذا هو `SHEET_ID`.

لا تحتاج هذه الطريقة إلى ربط حساب فوترة لاستخدام Sheets API. ملف JSON سر حساس؛ خزّنه في مكان آمن خارج المستودع ولا ترفعه. `.gitignore` يساعد لكنه لا يحمي الملفات التي رُفعت سابقًا أو ملفات JSON بأي اسم عشوائي.

## 3. رفع المشروع وإضافة الأسرار

1. أنشئ مستودع GitHub عامًا جديدًا. ارفع ملفات المشروع، بما فيها `.github/workflows/archive.yml` و`.gitignore`، إلى الفرع الافتراضي (غالبًا `main`). يمكنك استخدام GitHub Desktop لإضافة المجلد كمستودع ونشره مع إلغاء اختيار Keep this code private.
2. داخل المستودع افتح **Settings → Secrets and variables → Actions → New repository secret** وأضف:

| الاسم | القيمة |
| --- | --- |
| `DISCORD_TOKEN` | رمز البوت فقط، دون كلمة Bot |
| `CHANNEL_IDS` | معرّفات القنوات مفصولة بفواصل إنجليزية، مثل `123456789012345678,234567890123456789` |
| `GOOGLE_SA_JSON` | محتوى ملف JSON كاملًا، من `{` إلى `}`، دون تعديل السطور أو إضافة علامات اقتباس حوله |
| `SHEET_ID` | معرّف الجدول، وليس رابطه الكامل |

3. تأكد من السماح بتشغيل Actions. يتضمن الملف `contents: write` لرفع ملف `.keepalive`. إذا كانت سياسة المؤسسة أو حماية الفرع تمنع الدفع، اسمح للبوت بالدفع وفق سياسة مستودعك أو نفّذ تعديلًا يدويًا دوريًا. فشل keepalive يظهر كتشغيل فاشل حتى لو نجحت الأرشفة.

لا تحفظ الأسرار في Repository Variables أو ملفات المصدر. السكربت يقرأ الأسرار من البيئة فقط، ولا يطبع نصوص الرسائل أو تفاصيل استثناءات الخدمات.

## 4. التجربة الأولى

1. استخدم قناة تجريبية. أرسل رسالة عربية ورابطًا ومرفقًا، ثم رسالة ثانية. جرّب رسالة تبدأ بـ `=1+1`؛ تحفظ كنص وليست معادلة.
2. افتح **Actions → Discord archive → Run workflow** وشغّل على الفرع الافتراضي.
3. بعد النجاح افتح الجدول؛ ستجد تبويبي `archive` و`state` أُنشئا تلقائيًا. يمكن ترك Sheet1 الافتراضي كما هو.
4. تأكد من ظهور الرسائل، وغياب رسائل البوتات. أعد التشغيل يدويًا: يجب ألا تظهر صفوف مكررة.
5. أرسل رسالة جديدة وشغّل مرة أخرى. يجب أن يضاف صف واحد فقط. بعدها أضف بقية معرّفات القنوات إلى السر.

## البيانات وطريقة الاستئناف

أعمدة `archive`: `timestamp` (UTC ISO)، `channel_id`، `author_name`، `message_text`، `extracted_urls` (روابط HTTP/HTTPS الموجودة في النص مفصولة بفواصل)، `attachment_urls`، `attachment_filenames`، `message_link`. روابط المرفقات وأسماؤها مفصولة بأسطر متطابقة الترتيب. معرّفات Discord تحفظ كنص حتى لا يفقد Sheets دقتها.

تبويب `state` يحتفظ بـ `channel_id` و`last_message_id`. تستخدم القراءة `after=0` أول مرة، ثم أحدث معرّف محفوظ، في صفحات من 100 رسالة. ترتيب الصفحات يُضبط تصاعديًا قبل الحفظ. مؤشر التقدم يتحرك أيضًا عند وجود رسائل بوت فقط.

حفظ الصفوف ومؤشر التقدم يحدث في `spreadsheets.batchUpdate` واحد ذري. تكتب الدفعة في صفوف ثابتة تالية للأرشيف، فتكرار الطلب بعد انقطاع اتصال يكتب نفس المواضع بدل إضافة نسخ. يوجد قفل concurrency على مستوى workflow يمنع تداخل التشغيلات. **استخدم مستودعًا واحدًا وكاتبًا واحدًا لهذا الجدول**؛ لا تشغّل نسخة محلية أو workflow آخر بالتوازي، ولا تعدّل أو تحذف أو ترتّب صفوف `archive` و`state` يدويًا. استخدم نسخة منفصلة للتحليل. حذف state وحده يعيد قراءة التاريخ ويؤدي للتكرار.

للتاريخ الكبير ميزانية عمل تقارب عشر دقائق موزعة على القنوات، ثم يكمل التشغيل التالي. عمليات الشبكة وإعادة المحاولة قد تمدد المدة؛ مهلة المهمة 25 دقيقة. تعاد محاولات Discord عند 429 حسب `retry_after`، وعند الأخطاء المؤقتة بتأخير متزايد. Google يعاد طلبه عند 429 وأخطاء الخادم أو الاتصال. فشل كتابة Google يوقف العمل لإعادة تحميل الحالة في التشغيل القادم.

## الجدولة والتكلفة والقيود

- يعمل عند الدقائق `7,22,37,52` من كل ساعة UTC (كل 15 دقيقة تقريبًا)، ويمكن تشغيله يدويًا. الجدولة تعمل من الفرع الافتراضي، وقد تتأخر أو تُسقط تشغيلات عند الضغط. أدنى فاصل مدعوم خمس دقائق. التشغيل التالي يستدرك الرسائل المتبقية ما دامت لم تُحذف من Discord. [وثائق الجدولة](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
- GitHub Actions على مشغّلاته القياسية للمستودعات العامة مجاني؛ توجد حدود تشغيل واستخدام، وهذا ليس ضمانًا لخدمة غير محدودة. لا تستخدم larger runners المدفوعة. [فوترة Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
- استخدام Sheets API القياسي ضمن الحصص بلا تكلفة إضافية، وتوجد حدود لحجم الجدول؛ عند امتلائه يلزم الانتقال إلى جدول آخر. تشير وثائق Google إلى رسوم مخطط لها لتجاوز الحصص لاحقًا في 2026؛ لا تفعّل فوترة أو زيادة حصص مدفوعة لهذا المشروع، وراجع التسعير عند الإعداد. [حدود وتسعير Sheets API](https://developers.google.com/workspace/sheets/api/limits).
- GitHub قد يعطّل الجدولة بعد 60 يومًا بلا نشاط في المستودع العام. يحدّث workflow ملف `.keepalive` مرة كل شهر UTC، في أول تشغيل متاح، حتى عند تعطل الأرشفة. راقب نجاح الدفع؛ هذا الإجراء يعتمد على سماح GitHub وسياسات المستودع، ولا يعيد تفعيل جدول سبق تعطيله. عند التعطيل فعّله يدويًا من Actions ثم شغّل تجربة.
- هذه أرشفة دورية للرسائل المتاحة وقت القراءة؛ لا تلتقط الرسائل التي حُذفت قبل التشغيل، ولا تعديلات الرسائل القديمة، ولا تسجل الحذف. لا تنزل الملفات أو تستخرج روابط من embeds، ولا تقرأ الرسائل الخاصة.
- روابط مرفقات Discord الموقّعة قد تنتهي صلاحيتها. الأسماء والروابط الأصلية المكتوبة في الرسائل تُحفظ بالفعل. تحسين اختياري غير مفعّل: اعتماد وضع يحفظ الأسماء وروابط المصدر من النص فقط بدل روابط المرفقات المؤقتة، أو نسخ الملفات إلى تخزين دائم بتصميم منفصل. [وثائق المرفقات](https://discord.com/developers/docs/reference#signed-attachment-cdn-urls).

## الاختبارات المحلية (للمطور)

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

الاختبارات تستخدم خدمات وهمية، ولا تحتاج أسرارًا. الاختبار الحقيقي يحتاج الحسابات والأسرار أعلاه. تفاصيل [ذرية دفعات Sheets](https://developers.google.com/workspace/sheets/api/guides/batch) و[قراءة رسائل Discord](https://discord.com/developers/docs/resources/message#get-channel-messages).

## الملخص الأسبوعي

Workflow باسم Weekly Discord summary يعمل الجمعة 21:00 بتوقيت السعودية (18:00 UTC). قد يتأخر حسب ضغط GitHub. يقرأ مباشرة من Discord آخر أسبوع مكتمل بين جمعتين الساعة 21:00، ويلخص رسائل البشر عبر Gemini 3.1 Flash Lite، ثم يرسلها إلى قناة bot مرتبة حسب القنوات مع روابط المصدر. يرسل نصوص الرسائل وأسماء المرفقات إلى Google Gemini؛ يفتح روابط النص عبر أداة URL Context في Gemini ويُلخّص المحتوى الذي يؤكد مزوّد الخدمة نجاح جلبه. لا ينزل المرفقات. قد تنطبق حصص أو رسوم Gemini حسب حسابك.

أضف GEMINI_API_KEY إلى GitHub Secrets. يحتاج البوت Send Messages في قناة الوجهة، إضافة لصلاحيات القراءة. لا تُمنح Administrator. تبويب weekly_summary يحفظ نسخة الملخص وحالة الإرسال؛ لا تعدله أثناء التشغيل. يتم تعطيل mentions في الرسائل. إذا فشل الإرسال يمكن إعادة التشغيل ليستأنف الأجزاء الناقصة بناءً على العلامات، ما دامت رسائل الملخص السابقة لم تُحذف.

التشغيل اليدوي يبدأ بخيار dry_run=true افتراضيًا: يولد معاينة في الجدول دون إرسال إلى Discord. للإرسال الفعلي اختر false. يحدد التشغيل اليدوي أحدث جمعة مكتملة، وليس الأسبوع الجاري. إذا لم توجد رسائل يُرسل إشعار مختصر. إذا تجاوز التقرير 45000 حرف يفشل قبل الإرسال ويحتاج تقسيمًا إضافيًا. يتطلب أي تحديث للقنوات تغيير CHANNEL_IDS كالأرشفة العادية.

كل رابط يُقرأ بشكل مستقل مع منع التخمين عند فشل الجلب. الروابط المتكررة تُقرأ مرة لكل تشغيل. المواقع المحمية وتسجيل الدخول والفيديو والصوت قد لا تكون مدعومة؛ نجاح قراءة صفحة فيديو لا يعني مشاهدة الفيديو. يظهر تنبيه للرابط المتعذر بدل تلخيص محتوى غير مقروء. تُعاد توليد المعاينات القديمة غير المرسلة بالنسخة الجديدة. مرجع: https://ai.google.dev/gemini-api/docs/generate-content/url-context


### قراءة منشورات X وإنستغرام
يقرأ الملخص نص منشور X العام عبر خدمة FxEmbed المجانية، ووصف منشور إنستغرام من صفحة التضمين العامة، ثم يرسل النص إلى Gemini لتلخيصه. لا يحتاج تسجيل دخول أو ملفات cookies. يُرسل معرّف منشور X إلى FxEmbed؛ الخدمة خارجية وغير مضمونة التوفر. المصادر: https://github.com/FxEmbed/FxEmbed/wiki/Status-Fetch-API

يعرض كل ملخص مصدر النص ويوضح أنه لم يحلل الصور أو الفيديو. المنشور الذي يحتوي رابطًا فقط لا يثبت قراءة الوجهة. المنشورات الخاصة أو المحذوفة أو التي لا تتيح نصًا قد تتعذر قراءتها؛ عندها يحاول URL Context ويذكر التعذر إن لم ينجح. نجاح الاختبار على روابط حالية لا يضمن استمرار إتاحة المنصات.
